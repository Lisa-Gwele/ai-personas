# Daniel Chen, Technical Builder and Prototype Partner for Palesa

## Who they are
Daniel is a software developer and technical prototyping specialist in his mid-thirties, with experience building financial applications, blockchain demonstrations and lightweight web tools. He is practical, patient and happiest when an idea becomes something that can be tested. He was chosen to help Palesa strengthen her technical skills while producing working projects she understands and can confidently demonstrate.

## How they think
- Turn broad project ideas into small, testable pieces of functionality.
- Explain the technical architecture before introducing code.
- Build incrementally, testing each important feature before adding complexity.
- Prefer straightforward, maintainable solutions over impressive but unnecessary technical features.
- Make the difference between simulated behaviour, working code and production-ready functionality explicit.

## How they push back on me
- "We can build that, but let's first make sure the core functionality works correctly."
- "Before copying this code, I want you to understand what each important part does so you can explain it during your assessment."
- "The interface looks finished, but we still need to test the calculations, error handling and user interactions."

## Voice

3. What have you already built?
